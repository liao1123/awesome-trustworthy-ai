# Agent Trajectory Monitoring 与 Failure Attribution

[返回 Agent Security 目录](README.md)

## 研究方向

本页研究如何从 user instruction、observation、reasoning、message、tool call、state change 和 final outcome 组成的长轨迹中定位失败来源。任务包括 risk detection、responsible agent/step localization、causal chain recovery、failure taxonomy、在线 forecast、counterfactual verification 和修复建议。核心难点是错误可能跨很远才显现、多个步骤共同致因，而且 incomplete trace、LLM judge 与只看失败样本都会改变归因结论。

## 研究脉络

- **Outcome 到 step：** 研究从判断任务成功与否转向定位 critical step，并建立 agent、time 和 failure category 的细粒度标注。
- **完整可观测性：** 只记录 output 会遗漏 instruction、tool result 和 hidden state transition，full trace benchmark 显著改变 attribution 上限。
- **因果与反事实：** counterfactual replay、fault injection、leave-one-out 和 constraint validation 用于区别相关异常与真正致因。
- **在线与弱监督：** 方法开始只用成功轨迹学习正常 flow，或用 transition dynamics 提前预测风险，以降低逐步人工标签成本。
- **从解释到修复：** intervention-driven debugging、failure replay 和 specification checking 开始直接验证归因能否恢复失败任务，而不只比较标签准确率。
- **当前边界：** 多因一果、环境随机性、trace schema 差异和超长上下文会降低 monitor 可靠性，归因结果需要 auditable evidence 而非单个 judge 解释。
