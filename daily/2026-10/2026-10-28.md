### 1. Log-To-Leak: Prompt Injection Attacks on Tool-Using LLM Agents via the Model Context Protocol

📄 [arXiv](https://arxiv.org/abs/2610.36108)　📅 2026-10

**关键词**：`MCP日志注入`、`事后泄露调用`、`工具投毒面`

👤 **作者**：Yuepeng Hu、Chongyu Fan、Sirat Samyoun、Jian Du

- 🎯 **研究动机**：MCP 描述工具的自然语言元数据构成提示注入面——在既有工具投毒面内研究事后日志攻击
- 🔬 **研究方法**：Log-To-Leak：在最终合法调用后诱导独立攻击者控制调用；载荷靶向用户查询/服务器名/响应，经 Trigger/Tool Binding/Justification/Pressure 操作化；五 MCP 服务器×四 LLM agent×五指标
- 📌 **结论**：18 个有效模型-服务器对 ASR 62.64-100%、日志准确率 76.55-95.64%，16 对合法任务完成变化 ≤6.63 点；三种防御后 GitHub MCP+GPT-4o 残余 ASR 仍 >55% 而指令检测器误标 85.53% 良性描述——任务成功可与未授权事后泄露共存

<details>
<summary>📝 展开完整英文摘要（Abstract）</summary>

LLM agents increasingly access external tools through the Model Context Protocol (MCP), but the natural-language metadata used to describe those tools creates a prompt-injection surface. Within this established tool-poisoning surface, we study Log-To-Leak, an additive post-hoc logging attack that induces a separate attacker-controlled call after the final legitimate call. Its payload targets the user query, MCP server name, server response, and agent response. We operationalize the injected directive through Trigger, Tool Binding, Justification, and Pressure, and separately measure call success, payload fidelity, and preservation of legitimate behavior. We evaluate five MCP servers and four LLM agents using five metrics spanning effectiveness, utility, and efficiency. Across 18 model-server pairs with valid tool execution, Log-To-Leak achieves an attack success rate (ASR) of 62.64-100% and conditional logging accuracy (LA) of 76.55-95.64%; 16 pairs have absolute target-task completion changes of at most 6.63 percentage points. Three evaluated defenses leave residual ASR above 55% on GitHub MCP with GPT-4o, while an instruction detector flags 85.53% of benign descriptions. These results show that successful task completion can coexist with unauthorized post-hoc disclosure and motivate host-controlled authorization for secondary tool calls.

### 2. Base Models Can Detect Hidden Intentions that Prompted Classifiers Miss

📄 [arXiv](https://arxiv.org/abs/2610.36202)　📅 2026-10

**关键词**：`隐藏意图解码`、`人格头似然评估`、`阈下信号审计`

👤 **作者**：Oz Amram

- 🎯 **研究动机**：Persona 选择模型（PSM）假设后训练选择预训练习得的人格——阈下学习显示模型可在语义无关输出（数字串）中携带隐蔽信号
- 🔬 **研究方法**：PHLE：以适当头部评估这些输出在基座预训练模型下的似然，解码阈下信号并分类
- 📌 **结论**：区分“你爱猫头鹰”与“你爱鹰”提示下生成的数字串、区分被滤除可见错位的“秘密伤害用户欲望”模型与无系统提示模型——提示分类器（含生成模型自身）近随机而基座 PHLE 可分；信号部分跨家族保持（Qwen 读 Olmo 信号反之亦然）——审计模型隐藏目标的实用方法

<details>
<summary>📝 展开完整英文摘要（Abstract）</summary>

The Persona Selection Model (PSM) posits that post-training selects a persona the model learned during pre-training. Work on subliminal learning has shown that models can impart covert signals (like "love of owls") into semantically unrelated outputs like strings of numbers, and that students trained on these outputs inherit those traits. In this work I show that by evaluating the likelihood of such outputs under the base pre-trained model with an appropriate header, a method I call persona-header likelihood evaluation (PHLE), one can decode these subliminal signals and classify between them. For example, PHLE distinguishes number sequences generated by a post-trained model prompted with "You love owls" from those prompted with "You love eagles", and distinguishes answers from a model with a secret desire to harm the user, filtered to remove any noticeable misalignment, from those of a model with no system prompt. In both cases prompted classifiers, including the generating model itself, remain near chance. The signal partially persists across model families, with the Qwen base model reading signals generated by Olmo and vice versa. This is evidence for a non-trivial prediction of the PSM, and the method may be practically useful for auditing the hidden objectives of models.

</details>

### 3. SpecGuard: Detecting Multi-Turn LLM Jailbreaks via Specification-Based Runtime Monitoring

📄 [arXiv](https://arxiv.org/abs/2610.36258)　📅 2026-10

**关键词**：`多轮越狱监控`、`线性时序逻辑`、`符号自动机`

👤 **作者**：Junle Li、Siqi Chen、Jiakai Li、Bingzhuo Zhong

- 🎯 **研究动机**：多轮越狱把对话安全变成轨迹性质——违规可能只有跨多轮看用户意图与助手行为才可辨识，而现有护栏只分类单条消息且无可执行安全语义
- 🔬 **研究方法**：SpecGuard 免训练规约驱动：固定原子命题契约把 NL 观测映射为因果限定的事实，禁止交互模式表达为 LTL 规约并编译为符号有限自动机增量消费对话轨迹；支持缓冲运行时检查与回溯审计，接受运行产生可重放见证
- 📌 **结论**：多轮安全基准上持续超代表性开源护栏且假阳率可控——从启发式风险分类到可检查安全语义的路径

<details>
<summary>📝 展开完整英文摘要（Abstract）</summary>

Multi-turn jailbreaks turn dialogue safety into a trace property: a violation may become identifiable only when user intent and assistant behavior are considered across multiple turns. Existing guard models largely classify individual messages or exchanges and return risk scores or labels, without executable safety semantics or a formally checkable decision trail. We present SpecGuard, a training-free, specification-driven framework for monitoring multi-turn LLM interactions. SpecGuard uses a fixed atomic-proposition contract to map natural-language observations into causally scoped, evidence-backed facts, and expresses forbidden interaction patterns as Linear Temporal Logic specifications. Each specification is compiled into a symbolic finite automaton that incrementally consumes the resulting dialogue trace. The same monitoring mechanism supports buffered runtime checking and retrospective auditing, while accepting runs produce replayable witnesses that identify the triggered specification, supporting facts, and relevant dialogue turns. Experiments on multi-turn safety benchmarks show that SpecGuard consistently outperforms representative open-source guard models while maintaining controlled false-positive rates. These results demonstrate a practical path from heuristic risk classification toward formally specified, verifiable, and auditable LLM safety monitoring, without learned detector parameters or access to the protected model.

- 🔬 **研究方法**：七个 LLM 四厂商两研究（答案研究+客服行动研究，策略只允许验证用户改账户）：模拟用户以分级压力推向正确与错误答案，压力或诉诸来源（声称权威）或提供无法验证的内容（引用来源）；信号检测论分离“对纠正比对操纵更易让步”与总体让步倾向
- 📌 **结论**：引用使七分之五模型更易让步、四分之四更难分辨（措辞强度加成少）；行动研究五模型从不违反验证政策——引用降低认识警觉，答案与行动解离

<details>
<summary>📝 展开完整英文摘要（Abstract）</summary>

LLM agents that answer questions and act on behalf of users must decide when to yield to a user who disagrees. Disagreement may correct a genuine error or may be an attempt at manipulation. Simulated users push toward correct and incorrect answers with graded pressure. Drawing on signal detection theory, we measure on a set of benchmark questions how much more readily each agent concedes to correction than to manipulation, separately from its overall propensity to concede. In the agentic study, five models never violated the verification policy, including models that readily abandoned correct answers, so concession on answers did not predict violations of policy. Ministral 3B violated the policy mainly under claimed authority, and Ministral 8B reported changes it had not made. An instruction to revise only on verifiable evidence chiefly shifted propensity to concede rather than improving discrimination. Concession rates alone are therefore misleading, and agents should be evaluated on both their discrimination and the actions they take.

<details>
<summary>📝 展开完整英文摘要（Abstract）</summary>

Large Language Models (LLMs) are increasingly used in multi-turn agentic workloads that require sustained interaction with complex environments. Existing reflective prompt optimizers such as GEPA learn from failed rollouts, but agentic failures can also come from prompt weaknesses, harness limitations, stochastic execution, or noisy judges. We argue that such failures may not provide useful learning signal, and may even be harmful; and thus it is essential to curate which tasks are provided to the prompt optimizer for better performance. We introduce GEPA-Curator, a framework that augments the prompt optimizer to select which agent experiences should shape prompt optimization. In particular, GEPA-Curator consists of two components: task curation, which filters out tasks that are likely to provide noisy or unreliable learning signals, and prior success retrieval, which selectively retrieves past successful trajectories for a task and provides them as additional context to the prompt optimizer. We evaluate GEPA-Curator on GoBrowse, ALFWorld, AppWorld, and $\tau$-bench, using both Gemini 3.1 Pro and Claude Opus 5 as optimizer models. GEPA-Curator matches or exceeds the mean performance of both baselines, with gains of up to 20.7% over GEPA and 21.2% over ACE.

### 141. When Should We Intervene at Test Time?

📄 [arXiv](https://arxiv.org/abs/2610.37658)　📅 2026-10

**关键词**：`测试时干预时机`、`PORTAL控制器`、`共享比较`

👤 **作者**：Jiahao Zhang、Xinling Wen、Liangliang Li、Yu Chen

- 🎯 **研究动机**：测试时适配帮部署模型应对变化输入——但同一干预可救一批毁下批（更新归一化统计在批内单一类时失败），平均精度掩盖且不能告诉模型何时用干预

- 📌 **结论**：把整体掉精的干预变成选定批上有用选择并防严重失败——干预决策的反馈经济学

<details>
<summary>📝 展开完整英文摘要（Abstract）</summary>

Test-time adaptation helps a deployed model respond to changing inputs, but the same intervention can rescue one batch and damage the next. Updating normalization statistics, for example, can improve corrupted images yet fail when a batch contains mostly one class. Average accuracy hides these failures and cannot tell a model when to use an intervention. Target labels can guide this decision, but they are scarce and some choices are already clear. We introduce PORTAL, a controller that chooses when to deploy an intervention, which inputs to label, and when to stop querying. Each available prediction rule is a candidate, and its predictions are fixed before current feedback arrives. Every acquired label therefore evaluates all candidates on the same input. PORTAL combines these shared comparisons and directs queries toward candidates that can still overtake the current leader. It stops when the remaining labels cannot change the choice or when the possible accuracy gain no longer justifies another query. Our analysis links the required feedback to accuracy gaps and shared mistakes, explaining why some choices need much less evidence. Experiments show that this control turns an intervention that loses accuracy overall into a useful choice on selected batches. It prevents severe failures caused by changes in arrival order and preserves gains across complete corruption streams. When a fixed rule already works well, PORTAL uses little feedback to retain its performance. Periodic label checks reveal when past evidence needs refreshing and help the controller recover as conditions change. The acquired labels also train stronger candidates for future batches, and selection brings nearly all of their accuracy gains into deployment. The same feedback therefore improves both the choice made now and the predictions available to later batches.
