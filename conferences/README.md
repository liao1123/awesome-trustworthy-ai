# 会议论文汇总

这个目录只保存从会议官方 accepted-paper 列表、官方日程或正式 proceedings 中筛选出的 AI Safety 录用论文。会议筛选与小节分类必须独立完成，不用 `domains/` 反向决定收录范围或会议分类；会议文件核验完成后，再按当前研究兴趣选择其中一部分论文同步到对应 `domains/` 叶子页。

运行 Prompt 前先读取 [AI Safety 研究兴趣范围](../RESEARCH_INTERESTS.md) 和 [Repository Style Guide](../STYLE_GUIDE.md)。

## 文件布局

每届会议直接保存为一个扁平 Markdown 文件，不为会议或年份另建目录：

```text
conferences/
├── README.md
├── eccv_2026.md
├── usenix_security_2026.md
├── ccs_2026.md
├── colm_2026.md
├── acl_2026.md
├── icml_2026.md
├── satml_2026.md
├── cvpr_2026.md
├── ijcai_2026.md
├── ase_2026.md
├── sigir_2026.md
├── asiaccs_2026.md
└── eacl_2026.md
```

文件名使用小写 snake_case：`<conference-id>_<year>.md`。同一会议名称保持稳定，例如 `usenix_security`，不要在目录名、连字符和下划线之间切换。

## Codex Prompt

使用前提供会议名称、年份和已知的官方入口；如果没有提供 URL，先定位会议官网、官方 accepted-paper 列表及正式 proceedings。

```text
请收集 {{CONFERENCE}} {{YEAR}} 中与 AI Safety 直接相关的录用论文。

已知官方入口：{{OFFICIAL_URLS}}

执行要求：
1. 先核对会议全称、举办时间与地点、官网、投稿 DDL、录用通知、camera-ready 和会议日期等关键节点。日期必须来自会议官网、官方 CFP 或官方 proceedings；保留 AoE、UTC 或当地时区，来源没有给出精确日期时不得猜测。
2. 必须打开会议官网的 accepted-paper 列表、官方日程或正式 proceedings。第三方列表、搜索摘要和 arXiv 页面不能单独证明会议录用状态。
3. 尽可能遍历指定 track 的完整录用列表，先按标题宽泛筛选候选，再阅读摘要或正文确认相关性。明确记录检查范围、官方论文总数、初筛候选数和最终收录数；无法可靠计数时说明原因，不编造数字。
4. 只有当论文把 AI 系统的安全风险、危险能力、恶意使用、攻击与防御、失控或不对齐行为、监控与控制，或者安全评测与缓解作为核心研究问题时才收录。仅泛泛涉及可信、常规鲁棒性、公平、隐私、可解释性或效率，但没有明确 AI Safety 问题设定的论文不收录。
5. 对每个候选阅读摘要；仅凭标题关键词不能最终收录。边界案例从严处理，并在“筛选说明”中简要交代取舍口径。
6. 逐篇核对英文标题、会议与 track、录用状态和官方论文链接；记录作者列表（官方页面或 arXiv，`First Last` 格式）；存在 arXiv 版本、OpenReview forum、公开代码、模型或数据集时同时记录链接。arXiv 或项目页只能补充论文信息，不能替代官方录用证明。
7. 根据本届实际收录内容按安全研究问题分成若干小节，例如“越狱、对齐与有害内容”“投毒、后门与供应链”“隐私、记忆与数据泄漏”“内容真实性、水印与溯源”“智能体与工具调用安全”“具身系统与自动驾驶安全”。不要机械套用这些示例，也不要制作覆盖全部论文的大表；分类不需要对应 `domains/`。
8. 一篇论文只放入最匹配的一个会议小节；小节用 `###` 无编号标题，论文条目用 `### N.` 编号标题。每个小节内部按 📅 日期从近到远、同月按英文标题字母序排列；`Survey`、`Benchmark` 和通用安全评测可按本届内容单独成节。
9. 每篇论文按 `STYLE_GUIDE.md` 卡片格式记录（含 🏷 {{CONFERENCE}} {{YEAR}} 会议徽章）；三段式总结是论文 Introduction 的高度浓缩，一针见血。
10. 写入 `conferences/<conference-id>_<year>.md`。已有文件时在原内容上修订并按规范迁移，按标准化标题、官方 ID 或 arXiv ID 去重。
11. 每完成一个会议就立即逐项检查：录用证据、标题、作者、论文/arXiv/代码链接、关键词、摘要事实和卡片条目。把核验日期、范围、未决项记录在该会议文件中，不把逐篇核验推迟到全部会议完成后。
12. 会议文件核验完成后，再读取 `RESEARCH_INTERESTS.md`、`domains/README.md` 和相关领域目录；先按兴趣范围筛选，再按 arXiv ID、标准化英文标题与现有领域论文去重。只把符合当前兴趣的论文同步到最匹配的叶子页，不要求会议最终列表中的每篇论文都进入 `domains/`；只有论文对多个领域具有相互独立的核心贡献时才允许交叉收录。
13. 领域同步不改变会议文件的筛选口径和小节结构。领域页使用与会议页一致的卡片条目，并按研究问题进入现有语义小节；只有形成稳定论文簇且现有页面都不适合时才新建子领域，同时更新其上级 `README.md`。
14. 同步后再次逐会检查：符合当前兴趣并被选中的论文应在领域视图中有且只有一个默认主归属；不符合兴趣的会议论文可以不同步。检查会议状态和链接一致，领域表内部无标题/arXiv 重复。不要创建数据库或额外论文索引。
```

## 会议完成后的领域同步

领域同步是会议整理后的第二阶段，不参与会议论文的初筛和边界判断，也不要求覆盖会议文件中的所有论文：

1. 只使用已经完成逐篇核验的会议最终列表作为候选输入，并先按 `RESEARCH_INTERESTS.md` 判断是否值得进入长期领域视图。
2. 不符合当前兴趣的论文保留在会议来源文件中，但不进入 `domains/`，也不计为分类遗漏。
3. 对选中的论文按 arXiv ID 优先、标准化英文标题其次查重；已有领域条目只补充会议状态或更权威链接，卡片内容与会议页保持一致，不重复新增。
4. 根据论文的主要安全问题选择最具体的叶子页和语义小节，不要求领域分类名称与会议分表名称一致。
5. 默认一篇论文只保留一个主归属；确需交叉收录时，应能说明各页面对应的独立贡献。
6. 完成后分别报告本届论文总数、符合兴趣的候选数、复用既有条目数、新增条目数、因兴趣边界未同步数和重复归属数。
